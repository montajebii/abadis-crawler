# Architecture

## جریان داده

دستگاه‌های خزنده (Termux) هر کدام یک فایل CSV تولید می‌کنند، آن را در
`data/raw/` قرار می‌دهند و از طریق Pull Request به مخزن می‌فرستند.
GitHub Actions همه‌ی CSVها را ادغام و به SQLite تبدیل می‌کند و در Release
منتشر می‌کند.

## لایه ۱ — Crawler

مسئولیت: استخراج HTML صفحه‌ی فهرست، صف‌بندی واژه‌ها، باز کردن هر واژه و
استخراج بخش‌های معنایی، ذخیره‌ی وضعیت محلی برای ادامه‌ی کار پس از توقف.

نکات کلیدی:
- تقسیم کار بین دستگاه‌ها: هر دستگاه فقط حروفی را می‌گیرد که
  `hash(DEVICE_ID) % len(letters) == letter_index`.
- AIMD: نرخ درخواست به‌صورت پویا با موفقیت‌های متوالی افزایش و با ۴۲۹ کاهش می‌یابد.
- قبل از باز کردن هر واژه، چک می‌شود که قبلاً در `word_queue` با وضعیت
  `done` وجود ندارد.

## لایه ۲ — Transport

مسئولیت: انتقال CSVها از دستگاه‌ها به مخزن مرکزی بدون تعارض.

نکات کلیدی:
- نام فایل: `data/raw/<device_id>_<YYYYMMDD_HHMMSS>.csv` — یکتا برای هر اجرا.
- ورک‌فلوی `validate-pr.yml` هر PR را از نظر اسکیما بررسی می‌کند.
- چون هر دستگاه فایل جدا دارد، تعارض در سطح فایل رخ نمی‌دهد.

## لایه ۳ — ETL

مسئولیت: خواندن تمام `data/raw/*.csv`، حذف تکراری‌ها بر اساس
`(word_canonical, source_key)`، و درج در SQLite.

خروجی به‌صورت Release منتشر می‌شود تا حجم مخزن اصلی سبک بماند.
